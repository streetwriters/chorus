# Notesnook HA changes

This patch keeps the existing provider registry, Redis switch records, version vectors, and Asynq event queues.

- S3 client creation no longer probes synchronously or fails startup when a provider is down. A bounded background probe initializes optional `HealthReporter` state; Proxy HTTP requests refresh that state without changing the `Client` interface. The persisted routing policy is loaded from Redis after restart.
- During a zero-downtime switch, reads use the switch record's replication ID even though the replication policy is archived. A known source-only object is routed to its source; provider network failures return S3 `ServiceUnavailable` / HTTP 503. If the source is unreachable with repair events outstanding, the switch enters `PROMOTED_WITH_BACKLOG`: B is active, the switch no longer occupies the active-switch slot, and the repair event and switch task remain in Redis/Asynq. The switch reaches `DONE` after repair drains if A returns. New writes advance the old A→B version vector so delayed repair cannot overwrite newer B data; a B→C replication policy can be added while A→B repair remains pending.
- Deletes on the promoted target increment its version and enqueue an explicit reverse-direction delete event. Completed switch records remain available in request context for this purpose, and existing replication policies are still honored. Workers act only on explicit delete events and no longer infer deletion from missing version metadata or a missing source object. If an object sync event cannot be stored, Proxy returns retryable HTTP 503 instead of silently acknowledging it.
- Multipart uploads under replication are recorded in Redis with their initiating provider so routing remains correct across a switch. The marker is retained until the completion event is durably enqueued or the upload is aborted; ordinary uploads expire after seven days. If S3 completed an upload but event enqueue failed, a retry receiving `NoSuchUpload` verifies the final object with HEAD and re-enqueues its replication event.
- Query-string SigV4 GET, PUT, and multipart UploadPart are covered by the MinIO integration test. A test-only helper uses the exact AWSSDK.S3 3.7.310.8 package and Notesnook settings (`ServiceURL`, `AuthenticationRegion`, path-style, SigV4, `GetPreSignedURLAsync`).

## Verification and limits

Run Go commands with the repository's Go 1.26.6 toolchain. The MinIO integration test also needs .NET 8 and the AWSSDK.S3 3.7.310.8 NuGet package; it skips the SDK-specific case when `dotnet` is unavailable. Focused packages and `go test ./test/minio -count=1` pass, including the Notesnook-style presigned GET, PUT, and UploadPart checks. `go test ./... -timeout=180s` passed through `test`, then failed in `test/versioned` after its Testcontainers setup waited on external images; that environment-backed package exceeded the timeout.

The live Docker lab verified the blocked-event path: with A offline and a queued A-only object, switch status became `PROMOTED_WITH_BACKLOG`; Proxy and Worker restarted successfully; GET/HEAD of replicated data and new PUTs to B worked; the source-only read returned HTTP 503. The queued event remained pending and copied to B after A returned, moving the switch to `DONE`. The management CLI in the lab is older than this patch and renders the new enum as `NOT_STARTED`; query `/replication/switch/get` to see `PROMOTED_WITH_BACKLOG` until `chorctl` is updated.

Asynq object events use a retry cap of `MaxInt32`, which is operationally very large but finite. Health state is an initial probe plus Proxy request feedback; it is not a periodic Worker-side health service.

Multipart retry recovery depends on the Redis upload marker remaining available and unexpired. Ordinary upload markers expire after seven days; an upload abandoned longer than that may not be eligible for the `NoSuchUpload` reconciliation path. S3 object mutation and Redis enqueue are not atomic for non-multipart requests; Proxy reports queue failure as retryable HTTP 503, but durable replay still depends on the client retrying.
